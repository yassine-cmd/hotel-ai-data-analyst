# FMS — Deployment guide (single server)

Goal: any developer can take this repository and stand up a working FMS instance
on an existing LAMP server without guesswork. Every command is small and copy-pasteable.

The setup below puts everything on **one server** at `/var/www/fmsAgent`:

- Apache2 + **PHP 8.2 (php-fpm)** serving the Laravel app under `/fmsAgent`.
- A **Python 3.12** agent (uvicorn, port `8000`, loopback only) running in the
  background as a systemd service.
- A **Docker** sandbox used to run untrusted Python code (the agent spins up
  disposable `code-sandbox` containers built from `python:3.11-slim`).

Everything is on localhost, so no firewall tuning is required for a first deploy.

---

## 0. Prerequisites (assumed already on the server)

This guide assumes the target server is a standard LAMP host that **already has**:

- **Apache2** (with `mod_proxy` + `mod_proxy_fcgi` available — step 2 enables them).
- **MySQL / MariaDB** running, reachable on `127.0.0.1:3306`.
- **phpMyAdmin** installed.
- **PHP** installed — we assume the server's default is **PHP 7.4** and leave it
  untouched. FMS will get its own **PHP 8.2** installed alongside it.

What this guide installs fresh (because they are normally absent):

- **PHP 8.2** (fpm + modules), running only for the FMS app.
- **Python 3.12** + a virtualenv.
- **Docker** engine (for the sandbox).
- **Composer**, **Node.js / npm** (only if not already present) for building.

Other assumptions:

- A sudo-capable user.
- Outbound internet access (apt, pip, npm).
- About **2 GB RAM** free for the sandbox pool.

Run everything as that sudo user (not root) unless the command starts with `sudo`.

## 1. Copy the code (and what NOT to copy)

Copy the whole repository to `/var/www/fmsAgent`. The simplest way is to copy the
folder from your machine, e.g. with `scp -r` or an archive.

**Generated at build/run time — do NOT carry these as "source". The steps below
create them. If you copy a working checkout, just leave them out:**

| Skip                                  | Why it is recreated                                  |
|---------------------------------------|------------------------------------------------------|
| `venv/`                               | `python3 -m venv venv` + `pip install` (step 4)     |
| `node_modules/` (frontend)            | `npm ci` (step 8)                                    |
| `sessions/`                           | created at runtime by the Python agent              |
| `logs/`                               | created at runtime (keep `logs/.gitkeep`)            |
| `__pycache__/`, `*.pyc`, `*.egg-info` | recompiled on first run                             |
| `laravel/.env`                       | per-instance (DB creds, instance keys); create per instance, do NOT copy across clients |
| `laravel/bootstrap/cache/*`           | regenerated by Laravel                              |
| `laravel/storage/framework/*`         | regenerated; just needs to be writable              |
| `sandbox/container/`                  | Docker build output                                  |
| the `code-sandbox:latest` image       | built locally in step 5                             |

> **The Python root `.env` is different from `laravel/.env`.** It is a single
> *global* agent config (LLM key, `APP_HOST`/`APP_PORT`, `ADMIN_LARAVEL_URL`,
> `ADMIN_PUBLIC_KEY`, sandbox settings) — it is **not** per-client. It is fine, and
> recommended, to **copy/share the same root `.env` to every Python host** so all
> agents run with identical configuration and you avoid misconfiguration (see
> step 9). It is only `laravel/.env` that must be created independently per instance.

So a safe manual copy is the source tree **minus** the rows above. Example after
copying:

```bash
sudo mkdir -p /var/www
sudo chown "$USER":"$USER" /var/www
# copy the repo contents into /var/www/fmsAgent (excluding the list above)
ls /var/www/fmsAgent      # expect: agent/ config.py docs/ frontend/ laravel/ main.py requirements.txt sandbox/ ...
```

> Tip: if you package with `tar`, exclude them:
> `tar --exclude=venv --exclude=node_modules --exclude=sessions --exclude=logs \
>   --exclude=__pycache__ --exclude='*.pyc' --exclude='*.egg-info' --exclude=.env \
>   -czf fms.tar.gz .`

## 2. Install what is missing (PHP 8.2, Python, Docker, build tools)

Apache, MySQL, phpMyAdmin and the server's default PHP (7.4) are already there.
We **add** PHP 8.2 next to 7.4 and install Python, Docker and the build tools.

```bash
sudo apt update
sudo apt install -y software-properties-common
sudo add-apt-repository -y ppa:ondrej/php
sudo add-apt-repository -y ppa:deadsnakes/ppa
sudo apt update
sudo apt install -y \
  php8.2 php8.2-fpm php8.2-cli php8.2-mysql php8.2-mbstring \
  php8.2-xml php8.2-curl php8.2-zip php8.2-bcmath php8.2-gd php8.2-intl \
  python3.12 python3.12-venv python3.12-dev python3-pip \
  docker.io nodejs npm unzip git curl composer
```

Enable the services we add (leave the existing 7.4 / Apache defaults alone):

```bash
sudo systemctl enable --now php8.2-fpm
sudo systemctl enable --now docker
sudo a2enmod rewrite headers proxy proxy_fcgi setenvif
```

> The `ondrej/php` PPA provides **PHP 8.2** on top of the existing 7.4. The
> `deadsnakes/ppa` provides **Python 3.12**. Both install side-by-side; the
> server's existing 7.4 site is untouched.

### pdo_mysql socket for PHP 8.2 (avoid a common headache)

Laravel (running on 8.2) connects to MySQL over the Unix socket. Point 8.2's mysql
extensions at the running socket:

```bash
sudo sed -i 's#^;*pdo_mysql.default_socket =.*#pdo_mysql.default_socket = /run/mysqld/mysqld.sock#' /etc/php/8.2/cli/php.ini /etc/php/8.2/fpm/php.ini
sudo sed -i 's#^;*mysqli.default_socket =.*#mysqli.default_socket = /run/mysqld/mysqld.sock#' /etc/php/8.2/cli/php.ini /etc/php/8.2/fpm/php.ini
sudo systemctl restart php8.2-fpm
```

> If PHP 8.2 is a **custom build** (e.g. installed at `/opt/php8.2`), the ini files
> are `/opt/php8.2/etc/php.ini` (and `/opt/php8.2/etc/php-fpm.conf`); apply the same
> `sed` there and restart that service instead. The socket path stays
> `/run/php/php8.2-fpm.sock`, so the Apache `SetHandler` in step 6 is unchanged.

## 3. Create the FMS database (MySQL is already installed)

MySQL/MariaDB is already on the server. Create one dedicated database for FMS
metadata — either in **phpMyAdmin** or from the CLI:

```bash
sudo mysql
```

```sql
CREATE DATABASE agent_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'fms'@'127.0.0.1' IDENTIFIED BY 'STRONG_DB_PASSWORD';
GRANT ALL PRIVILEGES ON agent_db.* TO 'fms'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

Use a real password and remember it for `laravel/.env` (step 7).

---

## 4. Python: create the virtualenv and install dependencies

Use **Python 3.12** (the live server runs `3.12.10`). The sandbox image is
`python:3.11-slim` — that is independent and does not need to match the agent.

```bash
cd /var/www/fmsAgent
python3.12 -m venv venv
venv/bin/pip install --upgrade pip
venv/bin/pip install -r requirements.txt
```

This installs FastAPI, uvicorn, pandas, openai, the Docker SDK, etc. into `venv/`.

---

## 5. Docker: build the sandbox image

The agent runs user code in disposable containers from `sandbox/Dockerfile`.

```bash
cd /var/www/fmsAgent
sudo docker build -t code-sandbox:latest ./sandbox
```

The user that runs the Python agent must be able to talk to Docker. We run the
agent as the `fms` user (step 9), so:

```bash
sudo usermod -aG docker fms
```

## 6. Serve the FMS app under /fmsAgent on PHP 8.2 (leave 7.4 as default)

Laravel is mounted at the `/fmsAgent` subpath, so the existing default site and its
PHP 7.4 keep serving everything else. We add **one additive Apache config** that
scopes FMS to `/fmsAgent` and routes only its PHP to **php8.2-fpm** — this is the
same mechanism the reference server uses, and it does not touch the default site.

Create `/etc/apache2/conf-available/fmsAgent.conf`:

```apache
# FMS Agent (Laravel on PHP 8.2) served at /fmsAgent
# Additive config: scoped to /fmsAgent only; default site and php7.4 untouched.

Alias /fmsAgent /var/www/fmsAgent/laravel/public

<Directory /var/www/fmsAgent/laravel/public>
    Options -Indexes +FollowSymLinks
    AllowOverride None
    Require all granted

    DirectoryIndex index.php

    # Route .php under this tree to the PHP 8.2 FPM socket.
    <FilesMatch \.php$>
        SetHandler "proxy:unix:/run/php/php8.2-fpm.sock|fcgi://localhost"
    </FilesMatch>

    # SPA + API catch-all: non-file URLs go through the Laravel front controller.
    FallbackResource /fmsAgent/index.php
</Directory>
```

Enable it (do **not** edit or disable the existing default site / php7.4 config):

```bash
sudo a2enconf fmsAgent.conf
sudo systemctl reload apache2
```

> `FallbackResource` sends non-file URLs to `index.php`, so no `.htaccess` rewrites
> are needed. If the server's 7.4 uses `libapache2-mod-php7.4`, this `<FilesMatch>`
> `SetHandler` overrides it for `/fmsAgent` only; the rest of the server stays on 7.4.
> The socket path `/run/php/php8.2-fpm.sock` is the same whether PHP 8.2 came from
> the `ondrej/php` apt package or a custom build (e.g. `/opt/php8.2`).

## 7. Configure Laravel

```bash
cd /var/www/fmsAgent/laravel
composer install --no-dev --optimize-autoloader
cp .env.example .env
php artisan key:generate
```

Edit `laravel/.env` (minimum needed):

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=http://YOUR_HOST_OR_IP/fmsAgent

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=agent_db
DB_USERNAME=fms
DB_PASSWORD=STRONG_DB_PASSWORD

PYTHON_SERVICE_URL=http://127.0.0.1:8000
DATA_PLANE_SELF_URL=http://YOUR_HOST_OR_IP/fmsAgent/api/internal/data/v1

CLIENT_CREDENTIALS_KEY=
```

Create the credential-encryption key (printed value → paste into `CLIENT_CREDENTIALS_KEY`):

```bash
php artisan clients:key:generate
```

Run migrations, seed, link storage, fix permissions:

```bash
php artisan migrate --force
php artisan db:seed --force
php artisan storage:link
sudo chown -R www-data:www-data storage bootstrap/cache
sudo chmod -R 775 storage bootstrap/cache
```

Change the seeded admin password:

```bash
php artisan tinker --execute="App\\Models\\Admin::first()->update(['password'=>bcrypt('REPLACE_WITH_STRONG_PASSWORD')]);"
```

## 8. Build the frontend

```bash
cd /var/www/fmsAgent/frontend
npm ci
VITE_BASE_PATH="/fmsAgent/" VITE_API_BASE_URL="/fmsAgent" npm run build
sudo cp -a dist/. /var/www/fmsAgent/laravel/public/
```

The `VITE_BASE_PATH` / `VITE_API_BASE_URL` must match the `/fmsAgent` subpath above.

## 9. Run the Python agent in the background

Create the Python env file (copy the example, then fill in the LLM key and the
admin public key from step 7's key generation):

```bash
cd /var/www/fmsAgent
cp .env.example .env
nano .env
```

```dotenv
LLM_API_KEY=sk-your-key-here
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=deepseek/deepseek-chat

APP_HOST=127.0.0.1
APP_PORT=8000

ADMIN_LARAVEL_URL=http://127.0.0.1/fmsAgent
ADMIN_PUBLIC_KEY=<admin-public-key-from-laravel>

SESSION_DIR=/var/www/fmsAgent/sessions
AUDIT_LOG_FILE=/var/www/fmsAgent/logs/audit.log
SANDBOX_SKIP_BUILD=true
```

> `SANDBOX_SKIP_BUILD=true` is safe because we already built `code-sandbox:latest`
> in step 5. `ADMIN_PUBLIC_KEY` is the public half of the keypair you generate in
> step 10. You can fill it in after generating keys; then restart the service.

> **This root `.env` is global — share it.** Because it is one agent config for the
> whole deployment (not per client), copy the *same* file to every Python host rather
> than hand-editing each one. This matters most when Python runs on its **own server**,
> separate from the Laravel/FMS host: `ADMIN_LARAVEL_URL` must point at the admin
> Laravel instance (reachable over the private network, e.g. `http://ADMIN_PRIVATE_IP/fmsAgent`),
> and `ADMIN_PUBLIC_KEY` must match that admin instance's private key. If those two
> values drift between the Python host and the admin, client keys fail to verify (403)
> and analysis is rejected. Keep the Python `.env` identical across all Python hosts.

Create the systemd unit `/etc/systemd/system/fms-agent.service` (this is what runs
Python in the background and restarts it if it crashes):

```ini
[Unit]
Description=FMS Analytics Python Agent (uvicorn)
After=network.target docker.service
Wants=docker.service

[Service]
Type=simple
User=fms
Group=fms
WorkingDirectory=/var/www/fmsAgent
ExecStart=/var/www/fmsAgent/venv/bin/python /var/www/fmsAgent/main.py
Restart=always
RestartSec=3
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now fms-agent
sudo systemctl status fms-agent
curl http://127.0.0.1:8000/health
```

The `curl` should return `{"status":"ok", ...}`.

## 10. Create the admin/Python key pair

From the Laravel directory:

```bash
cd /var/www/fmsAgent/laravel
php artisan admin:keys:generate
```

- `PRIVATE` → `laravel/.env` as `ADMIN_PRIVATE_KEY`.
- `PUBLIC`  → root `.env` as `ADMIN_PUBLIC_KEY`.

Then restart Python so it picks up the new key:

```bash
sudo systemctl restart fms-agent
```

## 13. Troubleshooting

**Python not reachable (`curl .../health` fails):**

```bash
sudo systemctl status fms-agent
sudo journalctl -u fms-agent -n 100 --no-pager
ss -ltnp | grep 8000
```

**HTTP 500 after an `.env` change:**

```bash
cd /var/www/fmsAgent/laravel
php artisan optimize:clear
sudo systemctl reload apache2
```

**Sandbox errors (analysis runs but code execution fails):**

```bash
sudo docker images | grep code-sandbox
sudo systemctl status docker
id fms            # must be in the docker group
```

**DB connection / schema discovery fails:** check `DB_*` in `laravel/.env`, the
`pdo_mysql.default_socket` fix in step 2, and that `CLIENT_CREDENTIALS_KEY` is set.

## 14. Points of failure (common deploy mistakes)

### 14.1 Data-plane 404 — wrong deploy subpath (most common)

During analysis, Python calls back to Laravel's data plane at `DATA_PLANE_SELF_URL`
to run SQL and to report turn completion. If that URL **omits the subpath Laravel is
served under** (e.g. `/fmsAgent`), the `/api/internal/data/v1/*` routes never match
and every query fails with:

```
Query failed | error=Data plane returned non-JSON response (HTTP 404): ...
```

This also shows up in the agent log as raw `<title>404 Not Found</title>` bodies — it
is **not** a sandbox failure.

**Fix:** `DATA_PLANE_SELF_URL` (and `APP_URL`) must include the exact subpath:

```dotenv
APP_URL=http://YOUR_HOST_OR_IP/fmsAgent
DATA_PLANE_SELF_URL=http://127.0.0.1:80/fmsAgent/api/internal/data/v1
```

**Verify quickly** (no signature needed — a 403 proves the route matches, 404 proves
it does not):

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://127.0.0.1:80/fmsAgent/api/internal/data/v1/query
# 403 = correct (route matched, signature/Token required)
# 404 = still wrong (route not matched — fix the subpath)
```

After any change here run `php artisan optimize:clear` so the config is reloaded.

### 14.2 Sandbox (Docker) not reachable — Python/chart tool fails

Code execution runs in disposable `code-sandbox` Docker workers that the agent
reaches at `http://localhost:<port>`. If Docker is down, the image is missing, or the
agent user is not in the `docker` group, the Python tool and charts fail.

**Verify the sandbox is healthy:**

```bash
docker info >/dev/null 2>&1 && echo "docker OK" || echo "docker MISSING"
id fms | grep -q docker && echo "fms in docker group" || echo "fms NOT in docker group"
docker images | grep code-sandbox        # image must exist
docker ps                                # a worker container should be Up
```

The agent log should show at startup: `Sandbox pool connected | image=code-sandbox:latest`
and `Worker <id> spawned`. If no worker is `Up`, the pool could not reach Docker —
fix Docker/group/image, then `sudo systemctl restart fms-agent`.

> Do not confuse a **data-plane 404** (14.1) with a sandbox failure: a 404 means the
> URL/path is wrong; a sandbox failure surfaces as a connection/timeout error from the
> worker, not a 404.

## 15. Secrets & backups

Back up: `agent_db`, every `.env`, and `sessions/`/`logs/` if their retention
matters. Keep secret: `ADMIN_PRIVATE_KEY`, `CLIENT_PRIVATE_KEY`,
`CLIENT_CREDENTIALS_KEY`, the LLM API key, and analytics DB passwords. Never commit
`.env` files or private keys to Git.
